# Decisions

Why the project is shaped the way it is. One line of context, one line of
consequence — enough to avoid re-litigating a settled question, or to notice
when its premise no longer holds. Full ADRs live in `docs/adr/`.

| # | Decision | Why | Consequence |
| --- | --- | --- | --- |
| ADR 0001 | Chromium **overlay**, not a fork | A fork's diff becomes unmaintainable against Chromium's release cadence | Repo holds patches + `src_overrides/`; `build/sync.py` assembles the tree |
| ADR 0002 | One matcher interface, built-in C++ engine as default, adblock-rust as a swappable backend | Rust/FFI in the Chromium build for every platform costs more than owning the syntax long tail; the built-in engine is testable today without a checkout | `bedrock::blocking::FilterEngine` is the seam; either backend must pass the same tests |
| — | Licence: **MPL-2.0** for Bedrock's own code | Compatible with Chromium's BSD-3 base and with MPL-2.0 sources such as brave-core | GPL-3.0 sources (uBO, Privacy Badger) are idea sources only |
| — | `src_overrides/` preferred over `patches/` | A new file survives a Chromium rebase; a patch context does not | Patches are the last resort, one directory per upstream project |
| — | Pure logic is dependency-free and host-tested | CI cannot afford a 100 GB Chromium checkout, and untested logic is the default failure mode | Components avoid Chromium types in their core; `run_host_tests.sh` is the fast loop |
| — | Tor is a **transport mode**, not a security level | Putting it on the ladder implies "same but more" and implies anonymity | Separate control, separate wording, tested |
| — | Anti-fingerprinting normalizes first, noises only where normalization breaks the feature | Per-call randomness is itself a fingerprint | Deterministic derivation shared by every shim |
| — | Privacy statistics come from one event log | Three surfaces counting separately disagree within a week | DevTools, Privacy Center and the site panel all read the log |
| — | Presets are the source of truth, the UI detects rather than duplicates | A second table drifts silently | `Detect()` + apply→detect round-trip test |
| — | Zero telemetry as the shipped state, not a setting | "Anonymised telemetry" is still telemetry | Gate rejects reporting-shaped code |
| — | Performance claims need a number and a unit | "Blazing fast" cannot regress, so it cannot be defended | `check_perf_claims.py`; unmeasured budgets stay `pending` |
| — | Every gate is a script in `scripts/`, run on every PR | A rule nobody checks is a rule nobody follows | See `INVARIANTS.md` |
| 2026-08 | Project memory lives in `.ai/`, updated in the same PR as the change | Agents were re-deriving context by reading the tree, which is slow, expensive and lossy | `.ai/MEMORY.md` + `memory/`; `scripts/check_memory.py` enforces freshness |
| ADR 0003 | Subsystem tree under `src_overrides/bedrock/`, Chromium's layout where it owns the concept | Grouping by subsystem helps navigation; duplicating `base/`, permissions or site isolation fights the engine | Nested dirs; namespace names the subsystem, path names the placement; every directory needs a test and a `modules.json` line |
| ADR 0004 | C++ for engine and policy, Rust behind one FFI door, TypeScript only in WebUI, never Electron | Rust sprinkled through the browser process buys unsafe glue, not safety; a rewrite of working fuzzed C++ is not a safety win | `scripts/check_languages.py`; the first Rust candidate is the filter-list parser, if a campaign finds a bug there |
| 2026-08 (item 49) | Firefox is a *mechanism* source, per file and per licence — not a package | mozilla-central is mostly MPL-2.0 (file-level reuse possible), but its list data and vendored deps are not ours | `docs/research/FIREFOX.md`; follow-ups: letterboxing, "forget about this site", blocking `webRequest` ADR |
| 2026-08 (item 50) | Brave is the one source we may reuse *file by file* | brave-core is MPL-2.0, same as us, and MPL copyleft is per file | Each port needs that file's header, a notice row and the upstream commit; services and branding stay out |
| 2026-08 (item 51) | Never claim Tor Browser's properties, even after copying its mitigations | Tor's protection is its shared anonymity set; a Chromium browser has a different, smaller pool | Tor stays a transport mode; letterboxing and circuit display queued as honest, checkable wins |
| 2026-08 (item 52) | Filter lists are licensed **per list**, and none is a default until verified | The set mixes GPL-3.0, CC BY-SA, CC BY, CC0 and MIT; bundling any of them is distribution under its terms | `docs/privacy/FILTER_LISTS.md` + gate in `check_provenance.py`; shipped default set is empty for now |
| 2026-08 (item 55) | A feature carries a `Status`, and only `kEnforced` reaches the UI | A declared-but-undefined registry had the UI generated from a table that did not exist | Nothing is enforced until a build performs it and `build/ENFORCEMENT.md` records it; gate checks claims and counters |
| 2026-08 (item 56) | One settings table drives GUI, config file, policy and CLI; policy wins and locks | Four surfaces with four definitions drift, and the copy that drifts is the untested one | Strict parsing (errors, not shrugs); `docs/CONFIGURATION.md` checked against the table |
| 2026-08 (item 57) | Advanced settings return accept / warn / reject from one evaluator, with named guards | Power-user surfaces are where security models get quietly disabled, usually by a forum snippet | Policy is not exempt from the guards; every rejection names the guard it hit |
| 2026-08 (item 58) | Every reset states what it leaves alone; irreversible ones need the profile name typed | People avoid reset buttons because nothing tells them what survives | Backup export offered before destructive actions, reusing item 59 |
| 2026-08 (item 59) | Imported files are untrusted input and pass the item 57 guards | A settings file is an attacker-supplied configuration channel | Newer format versions are refused rather than partially read |
| 2026-08 (item 60) | Accessibility requirements are data with evidence, and mockups are gated | Overlay UI is where a Chromium fork breaks accessibility it inherited for free | No WCAG conformance claim until a real build can be audited |
| 2026-08 (item 61) | All strings live in one catalog under ids, with named placeholders and CLDR plural categories | Retrofitting i18n is a rewrite of every surface; positional placeholders break in all three non-English ship locales | A locale ships only when complete; Ukrainian falls back to English, never Russian |
| 2026-08 (items 62–64) | Windows/Linux supported, macOS best effort, platform macros confined to `platform/` | `#ifdef` creep turns one codebase into three, and the untested one rots | Bedrock-owned native surfaces need per-platform implementations behind interfaces |
| 2026-08 (item 64) | Detect capabilities through XDG portals; never assume a desktop environment | Desktop-specific assumptions are why applications feel foreign on most Linux desktops | Portal-first also makes the Flatpak build work; snap deliberately not produced |
| 2026-08 (item 65) | Keep the name Bedrock; mark is stone strata with one copper seam, plus a separate small-size variant | The name says what the project is without promising anonymity; below 32 px a six-band mark becomes a grey dot | The app icon never changes colour to signal state — state lives in the UI |
| 2026-08 (items 66, 69) | Security deadlines measured from the moment a fix is public upstream, features dropped rather than the release delayed | Nobody decides to fall behind; it happens one skipped roll at a time | Feature work must be revertible on short notice, so it stays in `src_overrides/` and behind flags |
| 2026-08 (item 67) | Every patch carries a Drop-When condition | A patch with no exit condition is a permanent maintenance cost that nobody dares delete | Patch review has one more question to answer, and the set stays small |
| 2026-08 (item 65, owner) | Keep the owner's artwork as the logo and write the name in Latin script in all locales | One spelling is what a user searches, types into a package manager and checks in a signature | Localised copy names the product in Latin inside a Cyrillic sentence; icons are generated from the PNG, so an SVG rebuild is a future task if one is ever needed |
| 2026-08 (item 71) | Bedrock's version is its own; the Chromium base is a separate mandatory field | Mirroring Chromium's version tells users the two are the same thing and makes "which Chromium is this?" unanswerable after a security roll | Every release note carries both numbers, and the code refuses a release whose base is not the pin |
| 2026-08 (item 71) | Unsigned builds are not releases, nightly included | An unsigned nightly is not faster, it is unverifiable, and nightly users are the ones running the least-tested code | Signing infrastructure is needed before the first nightly, not before the first stable |
| 2026-08 (item 70) | Release signatures are OpenSSH Ed25519 (`ssh-keygen -Y`), keys on offline tokens | Verification needs no new tool on any platform, and re-implementing signature checking in the verifier is how the verifier gets a bug | Key handling is the project's highest-value target; it is deliberately not in CI secrets |
| 2026-08-24 | Link cleaning unwraps a redirector only from a per-host rule, and only to an absolute http(s) target | A generic "parameter that looks like a URL" rule turns the cleaner into an open-redirect engine, and a URL it did not need to touch is a URL it should not rewrite | `url_cleaner` owns the one table; `BlockingPipeline::CleanUrl()` delegates; subresources are never cleaned |
| 2026-08-24 | "Forget about this site" shows its plan first and reports per-store outcomes, including `not available in this build` | A deletion action is worth only as much as the trust in its report; silent no-ops are how privacy features become folklore | Deleters are injected per store; passwords and bookmarks are opt-in; `complete()` is false if one store failed or was missing |
| 2026-08-24 | CNAME uncloaking never resolves on the decision path: `Canonical()` is cache-only and a miss is queued for the embedder to resolve with the user's resolver | A DNS round trip inside a 30 us decision would be paid by every request on every page to catch a tracker on the first request only, and a lookup made by the blocker itself would reach around the user's DNS choice | The first request to an unseen aliased host is not blocked, and that is stated in the feature disclosure; no resolver means no uncloaking, not a fallback |
| 2026-08-24 | An alias may only turn an allow into a block, never a block into an allow | Otherwise a tracker CNAMEs itself into a domain with an `@@` exception and buys immunity | Only `blocked` results from the aliased match are honoured; `kSameSite` and unlisted aliases change nothing |
| 2026-08-25 (audit) | An explicit per-host plaintext exception outranks HTTPS-Only; the per-site shields value does not | Clicking through an interstitial is a decision the user made about one host; a shields toggle is a coarse control that must never silently disable a mode | `https_policy` order, asserted in `https_policy_test`; `docs/security/AUDIT-2026-08-25.md` F2 |
| 2026-08-25 (F3/F4) | Keep a small, vector-verified crypto module in-tree instead of waiting for BoringSSL | Both audit findings were key-derivation bugs; leaving them until a build exists would have preserved them through the port, and published test vectors make a wrong implementation impossible to land | `src_overrides/bedrock/crypto/`, `docs/design/051-crypto-primitives.md` |
| 2026-08-25 (F3) | The AEAD tag is the master-password verifier; no stored verifier at all | A stored verifier needs a deterministic cipher (so it breaks under real AES-GCM) and an empty one accepts the first password offered | `password_store.cc` `UnwrapWithPassword()` |
