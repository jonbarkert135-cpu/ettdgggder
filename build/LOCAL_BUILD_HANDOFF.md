# Local Chromium+Bedrock build — handoff notes

Purpose: let the **next AI agent** (or human) continue without rebuilding
Chromium from scratch. Read this before touching anything under
`/work/chromium`.

Status date: 2026-08-27. Chromium pin: see `build/chromium.pin`
(151.0.7922.173, commit `a96602f30358e9b5d256a0464e7e4d4bec223004`).

A full stock build took **12 h 16 min** (56 105 steps, exit 0) on a 17-core /
448 GB host. Incremental rebuilds after editing 1–2 Chromium files take
**~30 s – 2 min per file** plus the final link.

The Chromium checkout and `out/` are **not** in git and cannot be: the repo
limit is 100 MB per file. Binaries will be published through GitHub Releases
at phase 16, not committed.

If the sandbox has been reset and `/work/chromium/src` is gone, re-create it before
building (this is the expensive path — about 40 min of fetching):

```bash
export PATH=/work/tools/bin:/work/chromium/depot_tools:$PATH
cd /work/chromium && fetch --nohooks --no-history chromium   # retry on network errors
cd src && git checkout --detach a96602f30358e9b5d256a0464e7e4d4bec223004
gclient sync -D --force --reset && gclient runhooks
cd /work/repos/ettdgggder && python3 build/sync.py --workspace /work/chromium --overlay-only
cd /work/chromium/src && gn gen out/Release --args='…'   # args below, minus enable_nacl
```

`enable_nacl` no longer exists in this Chromium; passing it makes `gn gen` fail. `build/sync.py`
needs `--workspace /work/chromium`; `scripts/resume_build.sh` passes it (it used to omit it and
exit 5) and takes the workspace root from `$BEDROCK_WORKSPACE`, default `/work/chromium`.

Always export first:

```bash
export PATH=/work/tools/bin:/work/chromium/depot_tools:$PATH
```

## 2. How the Bedrock code gets into Chromium

`build/sync.py --overlay-only`:
1. applies `patches/bedrock/**/*.patch` with `git apply --3way`;
2. symlinks every file of `src_overrides/` into `/work/chromium/src/bedrock/`.

So editing `src_overrides/bedrock/**` in the repo immediately changes the
Chromium tree. The GN glue is generated by `scripts/gen_build_gn.py --write`
into `src_overrides/bedrock/BUILD.gn` (one `source_set("bedrock")`), and
`patches/bedrock/build/0001-add-bedrock-to-chrome-browser.patch` adds
`"//bedrock"` to `//chrome/browser:browser`'s `public_deps`.

## 4. Errors hit so far and how they were solved

1. **No root / `apt` unusable.** Chromium's `install-build-deps.sh` cannot run.
   Solved by extracting Debian `pkgconf` + `libpkgconf3` `.deb` files with
   `dpkg-deb -x` into `/work/tools/root` and adding a wrapper script
   `/work/tools/bin/pkg-config`. Keep `/work/tools/bin` first in `PATH`.
2. **`-fno-exceptions`** in Chromium: overlay code must not use exceptions.
3. **`chromium-rawptr` clang plugin** rejects raw back-pointers. The overlay
   stays `//base`-free and its GN target uses
   `configs -= [ "//build/config/clang:find_bad_constructs" ]`; eight
   non-owning back-pointers were left as raw pointers deliberately.
4. **Standard headers must be included per file** (no transitive luck):
   103 overlay files were fixed.
5. **`ninja` refuses to run** when a siso state file is present
   (`out/Release contains Siso state file`). Use `autoninja`, not `ninja`.
6. **Sandbox restarts kill long compiles.** Relaunch detached:
   `setsid nohup bash -c 'autoninja -C out/Release chrome > log 2>&1;
   echo RC=$? >> log' & disown`. The build is incremental, nothing is lost.
7. **Runaway `git diff` in the Chromium tree** ate ~8 cores for 20 min and
   starved the build. Never run plain `git status/diff` in
   `/work/chromium/src` in the foreground — it is enormous and slow.
8. **siso scheduler stall** (2026-08-23): `siso` spun at >700 % CPU with
   `schedule pending:1+ready:0` and never spawned a compiler.
   Workaround that worked: compile the pending translation units by hand
   using the exact command from the target's `.ninja` file
   (`scripts/manual_compile.py` reproduces it), then let siso do the rest.
   Deleting `out/Release/.siso_fs_state` makes siso re-verify the whole graph
   (slow); a backup is kept as `.siso_fs_state.bak`.
9. **Stale object file → `undefined symbol` at link** (2026-08-23). Because the
   build was driven by hand around the siso stall, `obj/bedrock/bedrock/startup.o`
   was a day older than `src_overrides/bedrock/integration/startup.cc`, and mold
   failed with `undefined symbol: bedrock::integration::PrefDefaultOr(...)`.
   Nothing was wrong with the code. Rule: after editing any overlay file, recompile
   *its* object with `scripts/manual_compile.py` before linking, and compare
   timestamps (`ls -l obj/bedrock/bedrock/X.o` vs the source) when a symbol that
   clearly exists is reported missing. The reverse also bites: a stale
   `chrome_browser_main.o` kept logging a hook that had already been reverted in
   the source, so the binary printed lines the tree could not explain.
   **A failed link deletes `out/Release/chrome`** — that is normal, just relink.
10. **`error while loading shared libraries: libui_ozone.so`** when running the
   binary. This is a component build (`is_component_build=true`), so the loader
   needs the output directory: run with
   `LD_LIBRARY_PATH=/work/chromium/src/out/Release` (as `scripts/resume_build.sh`
   does) or `cd` into it first.
11. **`std::abs` is not visible in the modules build** (2026-08-27). Build 3 failed on its
   *last* step with `declaration of 'abs' must be imported from module
   '//build/modules:system.std.cstdlib' before it is required`, in
   `bedrock/privacy/network/request_headers.cc`. Including `<cstdlib>` does not help; the module
   has to be imported. Handle the sign by hand instead — and note the host tests (plain `g++`)
   cannot see this class of error at all, which is why `scripts/check_toolchain_limits.py` now
   greps for it before a push.
12. **Link timing.** The first (cold) mold link of `chrome` took **21 min 39 s**;
   every later link takes **13–15 s**. Do not assume a hang.

## 5. Verifying that Bedrock code is really inside the browser

```bash
cd /work/chromium/src/out/Release
nm -C chrome | grep bedrock:: | head
# for the startup log, launch it the same way as the DevTools snippet below
```

In a sandbox without D-Bus, a GPU or a working network, `--dump-dom` and `--screenshot` never
return: headless waits on shutdown work it cannot finish, and the process has to be killed
(exit 124). That is **not** a defect of the build. Drive the browser over DevTools instead — it
answers immediately:

```bash
LD_LIBRARY_PATH=$PWD ./chrome --user-data-dir=/tmp/bd --no-sandbox --headless=new --disable-gpu \
  --disable-dev-shm-usage --no-first-run --disable-component-update --disable-sync \
  --disable-background-networking --remote-debugging-port=9333 about:blank &
curl -s http://127.0.0.1:9333/json/version     # Chrome/151.0.7922.173, V8 15.1.206.23
```

Then `Target.createTarget` on a `data:` URL and `Runtime.evaluate` / `Page.captureScreenshot` over
the WebSocket (a WebSocket client must send no `Origin` header, or DevTools answers 403). This is
how Build 3 was verified to render and to run JavaScript.

Both checks passed again on 2026-08-27 (Build 4). `nm` finds **23** `bedrock::` symbols,
and the running browser prints:

```
[bedrock] effective user_experience_metrics.reporting_enabled = false (want false: match)
[bedrock] Balanced Privacy: 1 of 12 shipped defaults enforced by this build
[bedrock] registering (not decisive in this build) telemetry: user_experience_metrics.reporting_enabled = false
[bedrock] registering (not decisive in this build) crash_reporting: user_experience_metrics.reporting_enabled = false
[bedrock] enforcing webrtc_privacy: webrtc.ip_handling_policy = default_public_interface_only
[bedrock] effective webrtc.ip_handling_policy = default_public_interface_only (want default_public_interface_only: match)
```

The `effective ...` lines are the ones that matter: it is measured inside
`UpdateFromSystemSettings`, i.e. the value a live profile really hands to the
renderers, not a value the overlay printed to itself. Full log:
`/work/build-logs/run4c.log` (build 4); build 2's is `/work/build-logs/run2.log`.

**Proving a pref is the cause.** Set the assignment to the *wrong* value, rebuild (2–4 min) and
check the effective line reads `MISMATCH`. That is how build 4 found that the reporting-consent pref
does not decide anything in an unbranded build.

`scripts/resume_build.sh` runs sync + build + both checks in one go. Its startup check launches
the browser exactly as in the second snippet above (`--headless=new` plus the sandbox-safe flags)
and then asks it over the DevTools port (`--remote-debugging-port`, default 9333, override with
`$BEDROCK_DEVTOOLS_PORT`), waiting up to 60s. It never uses `--dump-dom`/`--screenshot`, which
hang here (see the note above). Verified end-to-end on 2026-08-27: `SCRIPT_RC=0`.

As long as `nm` prints no Bedrock symbols, nothing may be marked `kEnforced` in
`build/ENFORCEMENT.md` — that rule is enforced by
`scripts/check_no_fake_features.py`.
