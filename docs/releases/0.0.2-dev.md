# Bedrock 0.0.2-dev

**Channel:** nightly
**Released:** 2026-08-28

The build where the overlay starts *doing* things. `0.0.1-dev` enforced one preference; this one
blocks tracker requests inside the network service and cuts down outgoing request headers, and both
claims were measured on the running binary before this note was written.

the binaries themselves rather than from a hand-written list.

## Chromium base version

`151.0.7922.173` (commit `a96602f30358e9b5d256a0464e7e4d4bec223004`) — matches `build/chromium.pin`,
unchanged since `0.0.1-dev`.

## Security fixes

None of our own. The Chromium base is the same pinned revision as `0.0.1-dev` and is now **weeks
behind upstream stable**, so it is missing upstream security fixes released since. That is the single
biggest reason not to use this build as a daily browser yet.

## Privacy changes

Three protections are enforced by the running browser. Each line is a measurement, with the log
evidence recorded in `build/ENFORCEMENT.md`:

- **Tracker and ad request blocking** (new since `0.0.1-dev`). The network service asks
  `bedrock::integration::DecideRequest` before a URL loader is created; blocked requests fail with
  `net::ERR_BLOCKED_BY_CLIENT`. 18 built-in rules, third-party requests only, from the shipped
  defaults. Measured on bbc.com/news: `securepubads.g.doubleclick.net`,
  `sb.scorecardresearch.com` and `pagead2.googlesyndication.com` were refused while the page
  rendered; Google Analytics, Facebook and DoubleClick fetches that completed in `0.0.1-dev` now
  fail.
- **Outgoing header floor** (new since `0.0.1-dev`). A page declaring `Referrer-Policy: unsafe-url`
  — which Chromium honours — leaked no path to a third party, and high-entropy client hints are
  removed (measured: `Sec-CH-UA-Full-Version-List`, which Chromium sends to Google origins). The
  three low-entropy hints are kept deliberately: dropping them would make this browser more
  identifiable, not less.
- **WebRTC does not expose local network addresses** (`webrtc.ip_handling_policy` defaults to
  `default_public_interface_only`), as in `0.0.1-dev`.

What is **not** protected, despite existing in the source tree: fingerprinting surfaces are stock
(canvas readback, `navigator.hardwareConcurrency`, WebGL vendor strings are Chromium's), storage and
third-party cookies follow Chromium defaults, and there is no per-site control. `docs/WIRING.md`
counts it exactly: **5 of 33 overlay modules, 8 699 of 22 670 lines**, are reachable from the running
browser. Everything else compiles and is host-tested with no call site yet.

Also unchanged from `0.0.1-dev`: **no telemetry of ours** (there is no Bedrock server to talk to),
but upstream Chromium service traffic is not fully disabled, and two of the twelve shipped defaults
(`telemetry`, `crash_reporting`) cannot be enforced in an unbranded build at all — Chromium's metrics
service is compiled out without Google branding, so the browser logs them as *registered, not
decisive* instead of claiming a protection it does not provide.

## Dependencies

None added, removed or changed. No new third-party code: the two new protections are our own source
files plus patches into Chromium's network service. `docs/THIRD_PARTY.md` and `build/sbom.json` are
unchanged.

## Known issues

- Linux x64 only; no Windows or macOS build exists.
- Component build: it starts only through `run-bedrock.sh` (or with `LD_LIBRARY_PATH` set to the
  unpacked directory). No installer, desktop entry, auto-update or signature.
- **No Bedrock branding, name, icon, new-tab page or settings UI** — it looks and reads like
  Chromium, including Chromium's own privacy settings screens, which describe Chromium's behaviour
  and not Bedrock's. Where the two disagree, the browser's behaviour is what
  `build/ENFORCEMENT.md` records, not what the settings page says.
- Browser-level Google sign-in and sync cannot work: an unbranded build has no Google API keys, so
  `chrome://signin-internals` reports `Failure: Not authorized.` Signing into Google *websites*
  works normally.
- Blocking is process-wide from the shipped defaults; there is no UI to turn it off for a site, and
  the filter list is 18 built-in rules, not a subscription.
- Unstripped, unhardened, unaudited, and built by an automated pipeline with no independent review.
  Use a throwaway profile.
